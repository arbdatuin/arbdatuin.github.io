# Publishing guide

## Website repository: arbdatuin/arbdatuin.github.io

1. Extract the ZIP. Upload its contents (not the ZIP or enclosing folder) to the root of the existing repository on the main branch.
2. Commit the changes. Keep unrelated existing files.
3. In repository Settings → Pages, select Deploy from a branch, main, / (root), and Save.
4. Verify the homepage, career and skills pages, public résumé and seven project case studies.

## Optional GitHub profile README

Create a separate public repository named `arbdatuin` (matching the username). Copy `PROFILE-README.md` into that repository as `README.md`. Do not replace this website repository’s README with the profile version.

## Review before publishing

- Verify current employer/title and permission to disclose employer and deployment scale.
- Verify whether NAS capacity 19 is TB and raw or usable; verify RAID 1 and the reported 150 head office users / 250 branches.
- Confirm implementation dates, roles and metrics before expanding case studies.
- Use only approved sanitized evidence; avoid IPs, credentials, hostnames, serial numbers, employees and client data.
- Original résumé PDF, personal mobile and email are not published. The public résumé page has print styling.
